# 转码与压缩 · 总览

> 剪辑软件导出的是**母版**（画质优先、体积失控），平台与客户要的是**交付版**（体积 / 格式 / 规格优先）——中间这一步就是"转码与压缩"。本文按工具形态拆解：**GUI 批量转码**（HandBrake）、**命令行**（FFmpeg）、**剪辑软件自带导出**、**播放器应急转换**（VLC），帮你按场景选工具，而不是遇到"文件太大"就随便抓一个压缩软件。

## 为什么还要转码

创作者的视频文件其实分四层，每层的"最优解"不同，混在一起就会又慢又亏画质：

| 层级 | 目标 | 典型规格 | 由谁产出 |
| --- | --- | --- | --- |
| 母版 | 画质优先，二次加工的源头 | 高码率 ProRes / DNxHR / 高 RF 档 | 剪辑软件导出 |
| 交付版 | 平台 / 客户要什么给什么 | 平台规格内尽量好看 | 剪辑导出或转码工具 |
| 代理 | 剪辑流畅，画质无所谓 | 1/4 分辨率低码率 | 剪辑软件或转码工具 |
| 归档 | 多年可读、无损保存 | FFV1 / ProRes / 母盘 | 转码工具（HandBrake 1.11+ 内置预设） |

- **能一步到位就别两步**：如果剪辑软件导出时就能精确设成平台规格，直接导交付版即可，转码工具是"规格不匹配时的补锅侠"。
- **需要转码工具的典型时刻**：导出的母版太大传不上去；一批不同来源的文件要统一规格；客户临时要低规格小样；老素材要翻新归档。这些场景下，专门转码工具比反复开剪辑工程快得多。
- **压缩的画质经济学**：码率、画质、体积是一个三角，转码工具只能在给定编码器下帮你逼近"同画质更小体积"的理论线——新编码器（HEVC / AV1）比 H.264 同画质省约三到五成体积，代价是压缩更慢、部分老设备解码兼容差。**已经高度压缩的文件再压一遍，画质崩得比省下的体积快得多**：转码永远是"从高质量源往下压"，不要"从低质量源再压"。

> 判断自己要不要装转码工具，就看一句话：**你的母版和交付版之间，有没有经常隔着一道"体积 / 格式"的坎**。偶尔一次，VLC 救急；每周都有，装 HandBrake；每天都批量化，学 FFmpeg。

## 工具形态对比

| 维度 | HandBrake | FFmpeg | 剪辑软件导出 | VLC Convert |
| --- | --- | --- | --- | --- |
| 形态 | GUI + 预设 | 命令行 | 工程内导出 | 播放器附带 |
| 上手 | 选预设即用 | 需学命令语法 | 最顺手（本来就在剪） | 零门槛 |
| 质量控制 | 恒定质量 RF，成熟 | 全参数可控 | 取决于软件导出模块 | 基本不可控 |
| 批量 | 队列 + 文件夹扫描 | 脚本化无限扩展 | 逐工程渲染 | 无 |
| 转封装（无损） | 不支持 | `-c copy` 秒完成 | 通常不必要 | 不支持 |
| 拼接 / 剪切 | 不支持 | 支持 | 强项 | 不支持 |
| 适合谁 | 大多数创作者 | 愿意写命令的进阶用户 | 单一工程的最终导出 | 应急 |

- **HandBrake**：免费开源跨平台，预设体系 + 恒定质量 + 批量队列，是"批量把成片压成交付版"的默认答案。详见 [HandBrake](/contents/软件/视频/转码与压缩/HANDBRAKE.md)。
- **FFmpeg**：转码界的瑞士军刀，上面所有工具的底层引擎几乎都是它。GUI 工具干不了的活它都能干，代价是命令行门槛。两条最常用的命令值得背下来：无损转封装 `ffmpeg -i in.mkv -c copy out.mp4`（秒级完成、零画质损失，但两边的音视频编码格式必须都被目标容器支持）；批量压一整个文件夹 `for %f in (*.mov) do ffmpeg -i "%f" -c:v libx265 -crf 24 "%~nf.mp4"`（Windows 批处理写法，Linux/macOS 换 shell 循环）。没有独立档案规划，遇到具体需求按官方文档查命令即可。
- **剪辑软件导出**：单一工程的首选出口，规格可控、无中间损耗；劣势是"为压一个文件开整个工程"太重，且不擅长批量处理已有文件。
- **VLC Convert**：零门槛但无质量控制、无队列，定位是"顺手救急"，不承担正式交付。见 [VLC](/contents/软件/视频/播放/VLC.md)。
- 国产格式转换工具（格式工厂等）：中文界面友好，但编码器版本旧、广告与捆绑风险高，正式交付不建议。

## 场景选型

| 场景 | 首选 | 理由 |
| --- | --- | --- |
| 批量压缩交付版 | HandBrake | 队列挂机 + RF 恒定质量 |
| 只改容器不重编码 | FFmpeg `-c copy` | 秒级完成、零画质损失 |
| 多段拼接 / 抽帧 / 二次加工 | FFmpeg 或剪辑软件 | HandBrake 一进一出，做不了 |
| 单一工程最终导出 | 剪辑软件导出 | 无中间损耗 |
| 客户临时要低规格小样 | HandBrake | 从母版直压，不动工程 |
| 剪辑代理 | 剪辑软件或 HandBrake | 都能做，看团队习惯 |
| 长期压缩归档（个人留存） | HandBrake（x265 / SVT-AV1 预设） | 同画质体积小，兼顾体积与留存；见 [HandBrake](/contents/软件/视频/转码与压缩/HANDBRAKE.md) 的实战预设 |
| 机构级无损留存 | HandBrake（FFV1 / ProRes 预设）或 FFmpeg | 1.11+ 内置 Preservation 预设，数字典藏用 |
| 应急格式转换（装不了软件时） | VLC Convert | 有总比没有强 |

> 经验法则：**改"体积或规格"用 HandBrake，改"结构"（封装、拼接、剪辑）用 FFmpeg / 剪辑软件**。判断清楚要改的是哪一种，工具就选对了。

## 与相邻角色的边界

- **播放**：VLC 的转换是播放器的应急副业，本角色的正式工种见 HandBrake；两者对比见上表。
- **剪辑与调色**：剪辑软件内的导出参数怎么调属于剪辑工艺，见 [DaVinci](/contents/软件/视频/剪辑与调色/DAVINCI.md)；本栏只回答"导出之后还要不要过一道转码工具"。
- **交付与复盘**：交付版压成什么规格（码率 / 分辨率 / 编码器上限）由交付规范定义，见 [母版与交付规格](/contents/交付与复盘/导出与分发/母版与交付规格.md) 与 [平台规格速查](/contents/交付与复盘/导出与分发/平台规格速查.md)——工具管"压得准"，规格管"压成什么样"。
- **音频转码**：纯音频文件的播放与转码选型归 [音频 · 播放与转码](/contents/软件/音频/播放与转码/总览.md)，本角色只管视频（音轨随视频走）。
